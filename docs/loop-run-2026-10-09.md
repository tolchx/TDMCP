## 3. Ejecución — ítem 13 (`gauntlet-rojo`): **RESUELTO**

### 3.1 Diagnóstico — el «0 fases / 0 calls / 0.2 s» era un *crash de import*, no una aserción

Reporte `20261009-001009`: **F1 Smoke PASS** (9 calls, exit 0) · **F2 API core FAIL**
(`exit 1`, **0 calls**, 0.2 s, `failures: []`). Un FAIL **sin un solo call y sin fallos por assert** es
un **crash del script**, no un test que falló. Reproducción (sin pipe, exit real):

```
$ python tools/gauntlet/run_regression.py --quick
== F2  API core  (f2_core.py) ==
     Traceback (most recent call last):
       File ".../tools/gauntlet/f2_core.py", line 9, in <module>
         import live  # knowledge/live.py — los wrappers reales de producción
       File ".../knowledge/live.py", line 667
         '''
     SyntaxError: f-string expression part cannot include a backslash
   -> FAIL  (0 calls, p50 0 ms, 0 fallos, 0.1s)
QUICK_EXIT=1
```

### 3.2 Causa raíz

`f2_core.py` importa `knowledge/live.py`. Ese módulo está **modificado sin commitear** (WIP de otra
sesión del mismo working tree, mtime `2026-10-08 19:00:52`): agrega las secciones 7/8/9 y tres tools
live nuevas (`tdxn_export`, `eval_render_frame`, `get_op_errors_deep`) y las registra en `LIVE_TOOLS`.
La versión **commiteada** compila; la del **árbol** no:

```
$ git show HEAD:knowledge/live.py > "$LOCALAPPDATA/Temp/live_head.py"
$ python -c "import py_compile; py_compile.compile(r'$LOCALAPPDATA/Temp/live_head.py', doraise=True)"
HEAD live.py COMPILA OK                      # <- HEAD está sano

$ python -c "import py_compile; py_compile.compile('knowledge/live.py', doraise=True)"
  File "knowledge/live.py", line 667
    '''
SyntaxError: f-string expression part cannot include a backslash   # <- el árbol, roto
```

El defecto está en `t_eval_render_frame`: `save_script` es un f-string cuya **expresión** contiene un
backslash — `node.save({repr(tmp_target.replace('\\', '/'))})`. **TD 2025.32460 corre Python 3.11**, y en
Py < 3.12 una expresión f-string **no admite backslash** (PEP 701 lo habilitó recién en 3.12). Al ser un
error de **parseo del módulo**, tira abajo cualquier `import live` (⇒ server offline y gauntlet F2).

### 3.3 Fix (mínimo, no destructivo)

Hoistear el `.replace()` **fuera** del f-string, de modo que la expresión del f-string no tenga backslash:

```python
tmp_target_slash = tmp_target.replace('\\', '/')   # la sub-expr. con backslash queda AFUERA del f-string
save_script = f'''
...
        node.save({repr(tmp_target_slash)})
        print('<<JSON>>' + json.dumps({{"ok": True, "saved": {repr(tmp_target_slash)}}}))
...
'''
```

Comportamiento preservado (la ruta se sigue guardando con barras `/`). No se revirtió ni se deshabilitó
nada. `py_compile` OK · `import live` OK (**9 `LIVE_TOOLS`**).

> **Nota de alcance.** El fix toca el WIP sin commitear de otra sesión. El ítem de hoy es
> `gauntlet-rojo` (**accionable**; criterio de aceptación = «el síntoma ya no se reproduce»), a diferencia
> del `arbol-sucio` del 10-05 (decisión humana → el loop **no** toca el WIP). Por eso acá el fix **es** la
> ejecución del ítem, no un «arreglo de paso». El WIP en sí **no se commitea** (ver §6).
