## 3. Ejecución — ítem **11** del BACKLOG (decisión de esta corrida)

Sin candidato nuevo, el ciclo quedaba en no-op por **11ª corrida consecutiva** (10-10 → 10-19 todas
cerraron sin ejecución). En vez de otro no-op se tomó **el ítem abierto accionable que no necesita TD**:
el **ítem 11** — «el juez externo juzga el ÁRBOL ENTERO, no el diff del commit» — que es justamente
lo que contamina el veredicto del propio loop. Un ítem, nada más.

**Diagnóstico (código real, no memoria):**
`scripts/loop_gate.py::run_judge` armaba `python jev_audit_diff.py --repo ROOT --json` sin alcance;
`jev_audit_diff.py::archivos_cambiados` usa `git status --porcelain`, así que con cualquier WIP ajeno
en el working tree el juez difea archivos que **no entran al commit** y, si el diff crece, lo **trunca**
justo sobre el cambio que se va a publicar (evidencia reproducible del 2026-10-07 en el ítem 11:
mismo contenido → `ROJO corresponde=0.09..0.21 · diff_truncado` en el árbol real vs
`VERDE trabajo_real (0.99) · debilita=0.06` en un clon aislado).

**Fix (mínimo, un solo tema):** el juez pasa a correr sobre un **espejo aislado del commit**.

- `juez_scope(paths, root=None)` (nuevo, `scripts/loop_gate.py`): clona el repo con
  `git clone --shared --no-hardlinks` en un temporal (sin copiar objetos) y copia **sólo** el contenido
  del working tree de los `paths` del gate; un path borrado se borra también en el clon (la baja se
  refleja). Devuelve `(ruta, motivo)`; si falla, el llamador cae al árbol completo **avisando**.
- `run_judge(brief, paths=None)`: con `paths` corre el juez sobre el clon y lo borra en `finally`;
  el veredicto devuelto se anota con `scope` (`clon aislado` vs `arbol completo`).
- `main()` le pasa los `paths` del gate y **muestra qué archivos miró el juez**
  (`archivos_juzgados`), que es lo que hacía invisible el defecto.
- El alcance aislado se agregó a las suites del gate (`juez_scope_selftest`), así que a partir de ahora
  cada ALLOW prueba que el juez recibió exactamente el commit y no el árbol.

**Límite conocido (anotado, no arreglado acá):** un `rename` llega al juez como «alta del path nuevo»
(el gate sólo conoce el path final); el contenido juzgado es el mismo, el cambio de nombre no.

**Segundo defecto, encontrado al correr el gate de esta misma corrida:** con el alcance ya aislado el

push**, porque el visto bueno del juez no estaba; el commit siguiente, ya con 120.000, es el que lleva
